## 1. Назначение и границы

### 1.1. Цель

Расширение для Chromium-браузеров, которое локально, без единого сетевого запроса, находит в файлах `.docx` персональные и коммерческие данные и подменяет их плейсхолдерами, прежде чем файл попадёт в веб-сервис (LLM-чат или любую форму загрузки). Обратная операция — восстановление реальных значений в тексте ответа LLM по таблице соответствий.

### 1.2. Пользователь

Любой человек, работающий с договорами на русском и английском языке — прежде всего юристы. Открытый проект на общественных началах: исходники и релизы публикуются в открытом репозитории, установка — скачать `.zip` релиза и загрузить как распакованное расширение по инструкции в README. Публикация в Chrome Web Store не планируется (может быть добавлена позже без изменения кода); требования магазина к приватности и минимуму прав соблюдаются как инженерная гигиена. Расширение — инструмент, решение об анонимизации принимает человек: автоматический перехват выключен по умолчанию, основной путь — явная обработка в рабочем пространстве.

### 1.3. Сценарии (кратко, подробно — раздел 3)

- **С1. Явная обработка в рабочем пространстве** (основной). Вкладка расширения: один файл, партия файлов или папка → превью → правка → сохранение результатов, маппинга и отчёта.
- **С2. Перехват на сайте** (опциональный, включается в настройках). Пользователь выбирает/перетаскивает/вставляет `.docx` на разрешённом сайте → панель с найденными сущностями → правка и подтверждение → в сайт попадает обезличенная копия.
- **С3. Деанонимизация ответа.** Текст ответа LLM с плейсхолдерами → текст с реальными значениями.
- **С4. Настройка.** Страница настроек: перехват и сайты, категории (встроенные и свои), профили, исключения, экспорт/импорт конфигурации.

### 1.4. Вне рамок версии 1

| Что | Причина |
|---|---|
| Форматы `.doc`, `.pdf`, `.xlsx`, `.pptx`, `.rtf`, `.odt` | Решение заказчика; архитектура ядра допускает добавление через интерфейс `DocumentAdapter` (раздел 5.3) |
| Firefox, Safari | Решение заказчика; нет `chrome.offscreen` |
| Деанонимизация `.docx`, возвращённого сервисом | Решение заказчика: только текст |
| Анонимизация содержимого встроенных объектов (`word/embeddings/*`), диаграмм (`word/charts/*`), EXIF и визуального содержимого изображений | Отдельная задача; в v1 — предупреждение и опция удаления объектов (FR-15) |
| Формулы OMML (`<m:t>`), `numbering.xml`, `settings.xml` (`w:docVars`) | Текст с ПД встречается там крайне редко; предупреждение не выдаётся |
| Дообучение NER-модели на собственном корпусе | Берётся готовая модель; дообучение — риск R-2. **Версия 0.2:** вместо готовой NER-модели взята компактная `cointegrated/rubert-tiny2`, дообученная на открытом WikiANN ru+en (+ шаблонная синтетика, `tools/ner-train/`); собственного размеченного корпуса договоров по-прежнему нет |
| Синхронизация настроек между устройствами, общая конфигурация для команды, шифрование словарей паролем | Простота: экспорт/импорт конфигурации файлом (FR-53) достаточен |
| Публикация в Web Store, онбординг, телеметрия, обратная связь из расширения | Общественный проект: вопросы и ошибки — через issues репозитория |

## 2. Термины

| Термин | Определение |
|---|---|
| **Документ** | Один `.docx`-файл (ZIP-контейнер OOXML). |
| **Часть (part)** | Файл внутри ZIP, например `word/document.xml`, `word/header1.xml`, `docProps/core.xml`. |
| **Параграф** | Элемент `<w:p>` в любой части; может быть вложен в другой через `<w:txbxContent>`, `<w:sdtContent>`, `<w:tc>` и т. п. |
| **Ран (run)** | Элемент `<w:r>` с текстом `<w:t>`, `<w:delText>`, `<w:instrText>` и спецэлементами `<w:tab/>`, `<w:br/>`, `<w:sym/>`. |
| **Поток (stream)** | Непрерывная последовательность текста одного параграфа одного типа: `live` (`<w:t>`), `deleted` (`<w:delText>`), `field` (`<w:instrText>`). Поиск ведётся внутри потока; сущность не может пересечь границу потока. |
| **virtualText** | Строка потока после XML-unescape и нормализации спецэлементов (раздел 6.2). |
| **charMap** | Отображение индекс символа virtualText → (индекс рана, смещение внутри текста рана, байтовое смещение в XML-строке части). |
| **Сущность (entity)** | Найденный фрагмент данных: категория, нормализованное значение, список вхождений, источник, уверенность, статус валидации. |
| **Вхождение (occurrence)** | Одно место сущности в документе: часть, параграф, поток, диапазон virtualText. |
| **Категория** | Тип сущности из каталога (раздел 4.3): PERSON, INN и т. д. |
| **Плейсхолдер** | Строка вида `[ФИО_1]` / `[PERSON_1]`, которой заменяется сущность в режиме `placeholder`. |
| **Маппинг** | Таблица «плейсхолдер → исходное значение и его варианты» в формате JSON (раздел 4.6.4). |
| **База знаний (KB)** | Набор сущностей, извлечённых из блока реквизитов/подписей, и порождённых от них форм (склонения, инициалы, короткие названия). |
| **Детектор** | Источник кандидатов: `rule` (регулярка+лейбл+валидатор), `ner` (ML-модель), `kb`, `user`. |
| **Решение (decision)** | Выбор пользователя по сущности: `replace` (с текстом замены) или `skip`. |
| **Сессия документа** | Состояние разобранного документа и решений в памяти offscreen-документа, идентифицируемое `docId`; живёт до закрытия браузера или явного сброса. |
| **Ядро (core)** | Единый модуль разбора, поиска и замены, общий для всех точек входа. |
| **Хост обработки** | Контекст, где выполняется ядро: offscreen-документ расширения. |

## 3. Пользовательские сценарии

### 3.1. С1: рабочее пространство — один файл

1. Клик по иконке расширения → popup-меню → «Открыть рабочее пространство» (или горячая клавиша `Ctrl+Shift+Y`, или закреплённая вкладка `workspace.html`).
2. Пользователь перетаскивает `договор.docx` в зону загрузки (или «Выбрать файлы»). Прогресс «Чтение… / Поиск… / NLP…».
3. Через ≤ 10 с (30 стр.) — экран документа: слева таблица сущностей (фильтр, поиск, чекбоксы, редактируемые замены), справа вкладка «Текст» с подсветкой; сверху — профиль настроек («Для LLM» / «Для контрагента» / свой), режим замены, предупреждения.
4. Пользователь правит: снимает ложные срабатывания, выделением добавляет «Проект Орион» → «Анонимизировать как… → Новая категория/словарь».
5. «Сохранить результат» → системный диалог сохранения (`showSaveFilePicker`, имя по умолчанию `договор.anon.docx`); при недоступности API — обычное скачивание. «Сохранить маппинг», «Отчёт».
6. Документ остаётся в списке «Недавние» на боковой панели до закрытия браузера; к нему можно вернуться, изменить решения и пересохранить.

### 3.1a. С1: партия файлов и папка

1. Пользователь перетаскивает 7 файлов (договор + 6 приложений) или нажимает «Обработать папку» и выбирает каталог (`showDirectoryPicker`).
2. Появляется очередь: имя, размер, статус (ожидает / анализ / готов к проверке / сохранён / ошибка). Файлы анализируются последовательно; не-`.docx` помечаются «пропущен».
3. Маппинг партии — общий: сущности, найденные в первом документе, применяются ко всем следующим с теми же плейсхолдерами; таблица сущностей показывает столбец «в N файлах».
4. Пользователь проверяет документы по очереди (стрелки «предыдущий/следующий»); решения по сущности действуют на всю партию, кроме явных исключений конкретного вхождения.
5. «Сохранить все»: для папки — результаты пишутся в подпапку `anonymized/` исходной папки с теми же именами + `_batch.mapping.json` + `_batch.report.html`; для партии без папки — ZIP-архив `anonymized.zip` или по одному файлу.
6. «Применить маппинг…» на экране партии позволяет загрузить ранее сохранённый `*.mapping.json` — плейсхолдеры и варианты из него используются как базовая KB (одни и те же лица в допсоглашении через месяц получат прежние номера).

### 3.2. С2: перехват на сайте (включается пользователем)

0. Предусловие: в настройках включён «Перехват загрузки» и текущий сайт разрешён (по умолчанию — 5 LLM-сайтов). На иконке расширения бейдж `ON`.
1. Пользователь на `chatgpt.com` нажимает «Прикрепить» и выбирает `договор.docx` (или перетаскивает его в чат, или вставляет из буфера).
2. Content script перехватывает событие до обработчиков сайта, файл в сайт не попадает.
3. В правом нижнем углу появляется панель (Shadow DOM) «DOCX Anonymizer — договор.docx»: индикатор прогресса «Чтение… / Поиск… / NLP…» с процентами.
4. Через ≤ 10 с (документ 30 стр.) панель показывает таблицу: категория, значение, число вхождений, плейсхолдер (редактируемый), чекбокс. Сверху — фильтр категорий, счётчик «Найдено 47, включено 45», предупреждения (например, «2 встроенных объекта не обработаны»).
5. Пользователь снимает галочку с ложного срабатывания, правит плейсхолдер у компании, во вкладке «Текст» выделяет «Петров Иван» и выбирает «Анонимизировать как ФИО».
6. Нажимает «Анонимизировать и загрузить». Прогресс «Применение…».
7. В сайт подставляется `договор.anon.docx`, сайт показывает вложение. Панель показывает экран «готово»: «✓ Готово: заменено 46», основная кнопка «Скачать результат», меню «Ещё ▾» и «Закрыть».
8. Пользователь открывает «Ещё» → «Сохранить ключ восстановления» → сохраняется `договор.mapping.json` (ключ восстановления — карта замен, FR-28). Если он закрывает экран «готово», не сохранив ключ, один раз показывается подсказка «Сохранить ключ восстановления?» с кнопками «Сохранить» / «Понятно»; флаг `hintMappingShown` в настройках (не экспортируется), после него подсказка больше не появляется (редакция 0.3, WP10-D).

### 3.2a. Popup-меню

Popup — компактное меню без обработки файлов: «Открыть рабочее пространство», тумблер «Перехват загрузки» с указанием состояния на текущем сайте («включён на chatgpt.com» / «выключен» / «сайт не в списке — добавить?»), «Восстановить текст», список 5 последних документов, «Настройки».

### 3.3. С3: деанонимизация

1. Рабочее пространство, раздел «Восстановить» (также доступен из popup). Слева — поле «Текст с плейсхолдерами», справа — результат.
2. Маппинг берётся из текущей сессии (выпадающий список последних документов) или загружается из `.mapping.json`.
3. Вставка текста → мгновенная замена → кнопка «Копировать». Нераспознанные плейсхолдеры подсвечиваются.

### 3.4. Отказ от анонимизации

- В панели кнопка «Загрузить оригинал» → оригинал подставляется в сайт без изменений, сессия документа удаляется.
- Закрытие панели крестиком или Esc = «Загрузить оригинал» после подтверждения (одна кнопка «Да, загрузить оригинал»).
- Тумблер «Перехват на этом сайте: вкл/выкл» в панели и в popup.

### 3.4a. С4: настройка

1. Popup → «Настройки» (или `chrome://extensions` → «Параметры») — страница настроек во вкладке, разделы: **Перехват** (тумблер, режим сайтов, списки), **Категории** (встроенные с переключателями; «Добавить свою»), **Профили**, **Исключения**, **Обработка** (режим, язык, метаданные, лимит размера, NER), **Данные** (экспорт/импорт конфигурации JSON, очистка).
2. «Добавить свою категорию»: имя, префикс плейсхолдера RU/EN, цвет, тип (словарь / лейбл+форма / шаблон), поля типа, тестовое поле «Проверить на тексте» с подсветкой совпадений → «Сохранить». Категория сразу появляется в фильтрах и в превью.

### 3.5. Ошибки

| Ситуация | Поведение |
|---|---|
| Файл не ZIP / нет `word/document.xml` | Панель: «Файл повреждён или не является .docx». Кнопки: «Загрузить как есть», «Отмена». |
| Файл — OLE-контейнер (сигнатура `D0 CF 11 E0`) = зашифрованный `.docx` или старый `.doc` | «Файл зашифрован паролем или имеет формат .doc — обработка невозможна». Те же кнопки. |
| Размер > лимита (по умолчанию 50 МБ, настраивается до 100 МБ) | «Файл больше N МБ». Те же кнопки. |
| Расширение обновлено/перезагружено (`chrome.runtime.id === undefined` или ошибка «Extension context invalidated») | Панель: «Расширение было обновлено. Обновите страницу (F5). Файл загружен без изменений? Нет — файл не передан сайту». Content script перестаёт перехватывать до перезагрузки страницы; выбранный файл в сайт **не** передаётся автоматически — пользователь выбирает «Загрузить оригинал» или перезагружает страницу. |
| Offscreen-документ упал/не отвечает > 30 с | Background пересоздаёт offscreen и повторяет запрос 1 раз; при повторной ошибке — `ERROR` с кодом `HOST_UNAVAILABLE`. |
| Ошибка ядра (исключение) | `ERROR` с кодом и человекочитаемым текстом; кнопка «Скопировать отчёт об ошибке» (без содержимого документа). |
| PDF без текстового слоя (скан: на каждой странице < 20 букв) — `PDF_NO_TEXT` | «В PDF нет текстового слоя — похоже, это скан…». Те же кнопки: «Загрузить как есть» (оригинал уходит только после этого явного решения), «Отмена». |
| PDF с паролем — `PDF_ENCRYPTED`; без страниц — `PDF_EMPTY`; повреждён или не PDF при расширении `.pdf` — `PDF_INVALID` | Свой текст ошибки, те же кнопки. |
| Часть страниц PDF без текста | Обработка продолжается; предупреждение `PDF_PAGES_NO_TEXT` «Страницы N, M не содержат текста…» (§4.14). |

### 3.6. Повторная загрузка того же файла

SHA-256 содержимого совпадает с документом в сессии (в пределах браузерной сессии) → панель сразу показывает прежние сущности с прежними решениями и пометкой «Решения восстановлены из предыдущей обработки»; плейсхолдеры и номера совпадают с прошлым разом.

### 3.7. Несколько файлов

`input multiple` / drop нескольких файлов: `.docx` обрабатываются по очереди в одной панели с вкладками по файлам; остальные файлы проходят без изменений; итоговый `FileList` сохраняет исходный порядок. Нумерация плейсхолдеров — сквозная для всей партии (одно лицо в двух файлах → один плейсхолдер), маппинг — один на партию.

## 4. Функциональные требования

Формат: `FR-xx` — требование. **Приёмка:** проверяемый критерий.

### 4.1. Перехват на сайте

**FR-01.** Content script перехватывает выбор файла в любом `<input type="file">` на странице, включая элементы, добавленные после загрузки страницы и внутри открытых Shadow DOM (open mode).
**Приёмка:** на тестовой странице с 4 инпутами (статический, динамический через 2 с, внутри open shadow root, внутри iframe того же origin) выбор `.docx` в каждом открывает панель; обработчики страницы не получают событие `change` до подтверждения.

**FR-02.** Перехватывается drag-and-drop файла на любой элемент страницы (`drop` в фазе capture на `document`), если `dataTransfer.files` содержит `.docx`.
**Приёмка:** на тестовой странице с кастомной drop-зоной (React-style, `onDrop` на div) сброшенный `.docx` не доходит до обработчика до подтверждения; после подтверждения обработчик получает `DropEvent` с подменённым файлом на том же `target`.

**FR-03.** Перехватывается вставка файла из буфера обмена (`paste` с `clipboardData.files`).
**Приёмка:** аналогично FR-02 с синтетическим `ClipboardEvent`. Если сайт не принимает синтетический `ClipboardEvent` (проверяется по отсутствию реакции 2 с), панель предлагает «Вставить через кнопку прикрепления» с инструкцией.

**FR-04.** Определение `.docx`: расширение `.docx`/`.docm` без учёта регистра **или** MIME `application/vnd.openxmlformats-officedocument.wordprocessingml.document`. С версии 0.3 перехватывается и PDF: расширение `.pdf` или MIME `application/pdf`, если настройка `pdfMode` не `off` (§4.14). Файлы других типов проходят без изменений.
**Приёмка:** `.PDF`, `.doc`, `.zip` с переименованием — не перехватываются; `.DOCX` — перехватывается.

**FR-05.** После подтверждения content script подставляет новый `File` (имя `<name>.anon.docx`, тот же MIME) через `DataTransfer` в исходный `input` и диспатчит `input` и `change` (bubbles, composed) с флагом, исключающим повторный перехват.
**Приёмка:** на ChatGPT, Claude.ai, Gemini, DeepSeek, Perplexity вложение появляется в чате под именем `*.anon.docx`; повторный перехват не возникает (панель не открывается второй раз).

**FR-06.** `multiple` и несколько файлов — поведение по разделу 3.7.
**Приёмка:** drop 3 файлов (`a.docx`, `b.pdf`, `c.docx`) → сайт получает `[a.anon.docx, b.pdf, c.anon.docx]` в этом порядке.

**FR-07.** Перехват работает только если глобальный тумблер `interceptEnabled` включён **и** настройка `siteMode` разрешает текущий origin (раздел 4.8). По умолчанию тумблер **выключен**. На запрещённых сайтах и при выключенном тумблере content script не вешает обработчиков, не создаёт DOM и не открывает порт к background (нулевое влияние на страницу).
**Приёмка:** после установки без изменения настроек выбор `.docx` на любом сайте проходит без перехвата; включение тумблера → перехват на 5 сайтах allowlist без перезагрузки страницы; добавление origin в чёрный список → перехвата нет; `document.querySelector('docx-anonymizer-root') === null`.
> **Версия 0.2 (К9).** Третье условие — доступ к сайту, выданный пользователем (`optional_host_permissions`, `chrome.permissions.request` из popup или настроек). Content script не объявлен в манифесте: background регистрирует его только для выданных origin (`src/background/site-access.js`), поэтому на сайтах без доступа скрипта нет вовсе. Включение сайта в allowlist доступа не даёт; без доступа popup показывает «Нужен доступ…» и кнопку «Разрешить доступ» (§5.2 «Разрешения манифеста»).

**FR-08.** Панель — custom element с closed Shadow DOM, стили инкапсулированы, `z-index` 2147483647, не перехватывает фокус страницы до появления, закрывается по Esc (с подтверждением), перетаскивается за заголовок, запоминает позицию (per-origin, `storage.local`).
**Приёмка:** на 5 целевых сайтах панель видна поверх модальных окон сайта; стили сайта не влияют на панель (визуальный диф скриншотов панели на тестовой странице и на ChatGPT ≤ 1 % пикселей).

**FR-09.** Если `chrome.runtime.id` недоступен (контекст инвалидирован), content script снимает все обработчики и показывает сообщение по разделу 3.5 без обращения к API расширения.
**Приёмка:** нажать «Обновить» в `chrome://extensions` при открытой странице → выбор файла показывает сообщение, исключений в консоли нет.

### 4.2. Обрабатываемые части документа

**FR-10.** Текстовому поиску подвергаются потоки `live`, `deleted`, `field` всех параграфов, включая вложенные на любую глубину, в частях:
`word/document.xml`, `word/header*.xml`, `word/footer*.xml`, `word/footnotes.xml`, `word/endnotes.xml`, `word/comments.xml`, `word/commentsExtended.xml`, `word/glossary/document.xml`.
**Приёмка:** тестовый документ, в котором ИНН размещён в каждой из этих частей, в текстовом поле (`txbxContent`), в удалённом тексте рецензирования и в коде поля `HYPERLINK "mailto:…"` — все вхождения найдены (тест `parts.spec`).

**FR-11.** Атрибуты `w:author` и `w:initials` у `<w:ins>`, `<w:del>`, `<w:comment>`, `<w:rPrChange>`, `<w:pPrChange>` и прочих `*Change`, а также `w15:author` в `word/people.xml` и `w15:presenceInfo/@w15:userId` — обрабатываются как сущности категории PERSON (источник `rule`, подтип `author`) и заменяются согласованным плейсхолдером.
**Приёмка:** документ с правками трёх авторов → в результате 3 различных плейсхолдера, одинаковые для одного автора во всех атрибутах; `people.xml` не содержит исходных имён.

**FR-12.** Метаданные `docProps/core.xml` (`dc:creator`, `cp:lastModifiedBy`, `dc:title`, `dc:subject`, `dc:description`, `cp:keywords`, `cp:category`, `dc:identifier`), `docProps/app.xml` (`Company`, `Manager`, `HyperlinkBase`, `TitlesOfParts`) — по умолчанию очищаются (пустая строка, элемент сохраняется). `docProps/custom.xml` и `docProps/thumbnail.*` удаляются вместе с записями в `[Content_Types].xml` и `_rels/.rels`. **FR-13.** `Target` внешних связей (`TargetMode="External"`) во всех `word/_rels/*.rels` и `w:instr` в `<w:fldSimple>` сканируются детекторами EMAIL/URL; найденные значения заменяются: для EMAIL — `mailto:` + плейсхолдер, для URL — `https://anonymized.invalid/<placeholder>`. Внутренние связи не трогаются.
**Приёмка:** гиперссылка `mailto:ivanov@firm.ru` → `mailto:[EMAIL_1]`, ссылка кликабельна в Word (не вызывает ошибку открытия).

**Приёмка:** картинка с `descr="Паспорт Иванова И.И."` → `descr="Паспорт [ФИО_1]"`.

**FR-15.** Содержимое `word/embeddings/*`, `word/charts/*`, `word/media/*` не сканируется. Если такие части есть, пользователю выдаётся предупреждение «N встроенных объектов / диаграмм / изображений не анонимизированы» и опция «Удалить встроенные объекты и диаграммы» (удаляет части, их связи и ссылающиеся `<w:object>`/`<c:chart>`-элементы с заменой на пустой параграф). Изображения не удаляются.
**Приёмка:** документ с OLE-вложением `.xlsx` → предупреждение; с опцией — результат валиден и объекта нет.

**FR-16.** Текст замены XML-экранируется (`& < > " '`), поиск идёт по unescape-строке.
**Приёмка:** пользовательская замена `AT&T <Corp>` даёт валидный XML; документ открывается, текст отображается буквально.

### 4.4. Пересечения и приоритет

**FR-20.** Кандидаты, чьи диапазоны (в одном потоке) пересекаются, разрешаются по правилам в порядке:
1. `user` (добавлено/исправлено пользователем) побеждает всегда;
2. более высокий уровень уверенности: `validated` > `labeled` > `kb` > `ner` > `weak`;
3. при равном уровне — приоритет категории (таблица ниже);
4. при равном приоритете — раньше начавшийся;
5. при равном начале — более длинный.
Проигравший кандидат отбрасывается целиком (не обрезается).

Приоритет категорий (выше — важнее): PASSPORT, SNILS, INN, OGRN, ACCOUNT, CARD, IBAN, SWIFT, BIK, KPP, SSN, TAXID, EMAIL, URL, PHONE, BIRTHDATE, PERSON, COMPANY, ADDRESS, CONTRACT, AMOUNT.

**Приёмка:** фикстура `overlap.json` c 20 случаями (ИНН внутри телефона, ФИО внутри названия компании «ИП Иванов Иван Иванович» → COMPANY целиком, адрес, содержащий «ул. Ленина» и NER-LOC) даёт ожидаемый результат.

**FR-21.** Внутри COMPANY с ОПФ «ИП» ФИО не выделяется отдельно, но ФИО попадает в KB как PERSON-вариант той же стороны, чтобы его отдельные упоминания получили плейсхолдер той же стороны: `ИП Иванов И.И.` → `ИП [ФИО_1]`; далее «Иванов» → `[ФИО_1]`.
**Приёмка:** тест `kb-ip.spec`.

### 4.5. База знаний сторон

**FR-22.** Ядро находит блок реквизитов: параграфы после заголовка из списка («Реквизиты сторон», «Адреса и реквизиты», «Юридические адреса», «Подписи сторон», «Signatures of the Parties», «Details of the Parties», «Notices») до конца части, либо, если заголовок не найден, последние 25 % параграфов `word/document.xml` плюс все таблицы с ≥ 2 лейблами из категорий INN/KPP/OGRN/ACCOUNT в одной таблице. Преамбула (первые 10 % параграфов или до первого параграфа, начинающегося с «1.») также сканируется на конструкции «<КОМПАНИЯ>, в лице <должность> <ФИО>, действующего на основании».
**Приёмка:** на корпусе (раздел 8) блок реквизитов определён верно в ≥ 95 % документов (ручная разметка границ блока).

**FR-23.** Из блока извлекаются PERSON и COMPANY (всеми детекторами) и для каждой порождаются варианты:
- PERSON (RU): все падежные формы фамилии, имени, отчества по правилам русской морфологии (суффиксы -ов/-ев/-ин/-ский/-ая/-ич/-на и т. д., ≥ 95 % покрытие на тестовом списке из 500 ФИО), формы «Фамилия И.О.», «И.О. Фамилия», «И. О. Фамилия», «Фамилия И. О.», «Имя Фамилия», одиночная фамилия (только если фамилия длиной ≥ 4 букв и не входит в словарь нарицательных слов из 50 000 лемм);

- COMPANY: полное название с ОПФ, название без ОПФ, название в кавычках любого типа («», “”, "", ''), транслитерация RU↔EN по ГОСТ 7.79-2000 (система Б) и по ИКАО, аббревиатура из заглавных букв слов названия (если ≥ 2 слов).
Варианты ищутся по всем частям и потокам без учёта регистра, с границами слов; найденные вхождения присоединяются к сущности-источнику (один плейсхолдер).
- PERSON третьих лиц (версия 0.2, WP7 — ступень 1 NER): словарный детектор по всему документу без лейблов. Словари: русские фамилии (50 000 лемм) и имена (≈ 6 800, с родом) — datacoon/russiannames (BSD-3-Clause), имена-омонимы — natasha (MIT), английские имена и фамилии — US Census (public domain); генератор `npm run dicts`, атрибуция — `src/core/detect/names/dict/NOTICE.md`. Правило «два признака из трёх»: имя по словарю в любом падеже, отчество по суффиксу, фамилия по словарю или суффиксу; шаблоны «Имя Фамилия»/«Фамилия Имя» (с согласованием рода и падежа, если фамилия не словарная или имя — омоним), «Имя Отчество», ALL CAPS — только со словарной фамилией, латиница «First Last»/«First I. Last». Не срабатывает после топонимов («ул.», «им.», «г.»), в кавычках, в названиях госорганов, в устойчивых сочетаниях («Иван Купала», «Лада Веста»); в начале предложения и в заголовках требует словарного попадания. Вхождения — уровень `kb`, лицо не становится стороной; записи с ≥ 2 попаданиями ищутся по документу в парных формах (одиночная фамилия — только для сторон). Настройка `dictNames` (по умолчанию вкл.).

**Приёмка:** тест UI.

### 4.6. Режимы замены, ручные правки, маппинг

**FR-25.** Режимы: `placeholder` (по умолчанию), `mask`, `delete`.
- `placeholder`: `[ПРЕФИКС_n]`, где `n` — порядковый номер сущности в категории по первому вхождению в порядке обхода частей (document → headers → footers → footnotes → endnotes → comments → glossary → metadata); одинаковое нормализованное значение → один плейсхолдер (нормализация: trim, схлопывание пробелов, lower-case для PERSON/COMPANY/EMAIL/URL, удаление разделителей для числовых категорий).
- `mask`: замена каждого буквенно-цифрового символа на `X` (цифры → `0`? нет: все на `X`), разделители сохраняются; длина сохраняется. Пользователь предупреждается в UI: «Маска раскрывает длину значения».
- `delete`: сущность заменяется на `[удалено]` / `[redacted]` (не пустая строка — чтобы текст не склеивался).
**Приёмка:** фикстура `modes.json`.

**FR-26.** Пользовательские правки замены (поле «Замена» в превью) имеют приоритет над режимом: если пользователь ввёл текст, он используется в любом режиме; переключение режима не стирает правки (закрывает дефект 6). Переключение режима предлагает «Сбросить ручные замены?» с кнопками «Оставить» / «Сбросить».
**Приёмка:** тест UI: ввод замены → смена режима → замена сохранена.

**FR-27.** Маппинг формируется во всех режимах (в `mask`/`delete` поле `placeholder` содержит фактический текст замены) и доступен для скачивания и из рабочего пространства, и из панели на сайте (закрывает дефект 6).
**Приёмка:** кнопка «Скачать маппинг» есть в обоих UI; файл валиден по JSON-схеме.

**FR-28.** Формат маппинга — JSON по схеме `schemas/mapping.schema.json`:

```json
{
  "schemaVersion": 1,
  "createdAt": "2026-10-02T10:15:00Z",
  "tool": { "name": "DOCX Anonymizer", "version": "1.0.0" },
  "mode": "placeholder",
  "language": "ru",
  "documents": [
    { "name": "договор.docx", "sha256": "ab12…", "resultName": "договор.anon.docx" }
  ],
  "entries": [
    {
      "placeholder": "[ФИО_1]",
      "category": "PERSON",
      "original": "Иванов Пётр Сергеевич",
      "variants": ["Иванова П.С.", "П.С. Иванов", "Иванову Петру Сергеевичу"],
      "occurrences": 14,
      "source": "kb",
      "parts": ["word/document.xml", "word/footer1.xml"]
    },
    {
      "placeholder": "ООО «[КОМПАНИЯ_1]»",
      "category": "COMPANY",
      "original": "ООО «Ромашка-Трейд»",
      "variants": ["Ромашка-Трейд", "Romashka-Trade LLC"],

    }

```

**Приёмка:** валидация схемой в тестах; `entries` отсортированы по категории и номеру.

**FR-29.** Маппинг и содержимое документа **никогда** не записываются в `chrome.storage.local`/`sync`, IndexedDB или файлы без явного действия пользователя. Сессия документа живёт в памяти offscreen-документа; индекс сессий (docId, имя, sha256, дата, решения пользователя — без исходных значений) — в `chrome.storage.session`. При закрытии браузера всё удаляется.
**Приёмка:** после обработки `chrome.storage.local.get(null)` не содержит строк документа (тест ищет известное значение ИНН из фикстуры во всех хранилищах); `storage.session` содержит только решения с ссылками на `entityId`.

### 4.9. Деанонимизация

**FR-36.** Раздел «Восстановить» рабочего пространства (и из popup) заменяет плейсхолдеры на `original` из выбранного маппинга. Распознаются формы: точная `[ФИО_1]`; без скобок `ФИО_1`; с пробелом/дефисом вместо `_`; в обёртках Markdown (`**[ФИО_1]**`, `` `[ФИО_1]` ``, `_[ФИО_1]_`); с другим регистром; с ОПФ-обёрткой (`ООО «[КОМПАНИЯ_1]»` → `ООО «Ромашка-Трейд»`). Нераспознанные конструкции вида `[…_n]` подсвечиваются жёлтым и перечисляются внизу.
**Приёмка:** фикстура `deanon.json` с 30 случаями; 100 % совпадение.

**FR-36а** (редакция 0.3, WP10-B). Ответ ИИ можно восстановить и **файлом**: на странице «Восстановить» режим «Файл от ИИ» принимает `.docx`/`.docm` и `.md`/`.markdown`/`.txt` (лимит — `maxFileSizeMB`). Карта — из недавней обработки (запрос `GET_MAPPING` к хосту) или из `.mapping.json`; замена выполняется на странице ядром. Текстовый файл восстанавливается как текст FR-36; DOCX — `restoreDocx()`: обратная замена во всех потоках (тело, таблицы, колонтитулы, сноски, комментарии, авторы правок, поля и `fldSimple`, alt-тексты, внешние ссылки, docProps) с сохранением форматирования — значение пишется в первый ран плейсхолдера, остальные раны остаются пустыми; `https://anonymized.invalid/[URL_n]` в связях → исходный URL; метаданные сохраняются; части, которых замена не касается (в т.ч. `vbaProject.bin`), копируются побайтно. Результат скачивается как `имя.restored.<расширение>` (суффикс анонимизации снимается: `договор.anon.docx` → `договор.restored.docx`). Для DOCX показываются число замен, склонённые ФИО («падеж · значение в карте → подстановка») и нераспознанные метки. `restore.html?docId=…` предвыбирает обработку (неизвестный `docId` — самая свежая). Ограничения: инициалы автора (`w:initials`) восстанавливаются полным именем; записи режимов `mask`/`delete` не восстанавливаются; ФИО в косвенном падеже, заменённое общим плейсхолдером, восстанавливается формой из карты (или по FR-37).
**Приёмка:** `tests/unit/restore-doc.spec.js` (форматирование, все виды потоков, круговой прогон образца: 100 % меток восстановлены, текст потоков совпадает с исходным), `tests/unit/deanon-spans.spec.js`, e2e `restore.spec.js` (`.md` и `.anon.docx` → `*.restored.*`, `?docId=`).

**FR-37** (редакция 0.2). Для PERSON в форме `[ФИО_n]` падеж подбирается по контексту метки: (1) окончание, приклеенное к метке (`письмо [ФИО_1]у` → «Иванову Петру Сергеевичу»; `[ФИО_2]ой`, `[ФИО_1]ым` и т.п., с учётом рода), окончание поглощается; (2) иначе предлог или управляющее сочетание в окне до 3 слов перед меткой (`от`, `к`, `с`, `о`, `про`…, `от имени`, `в адрес`, `в лице`; допустимы слова-мостики `г-н`, `уважаемый`, `директор`…); (3) иначе падеж предыдущей склонённой метки при сочинении (`от [ФИО_1] и [ФИО_2]`). При неуверенности (`в/на/за/под`, незнакомое окончание, латиница, неоднозначное значение) подставляется именительный падеж. Лемма и род выводятся из `value` (и `variants`) записи — по отчеству, словарю имён или фамильному суффиксу; карта замен не меняется. Склонённые подстановки подсвечиваются (зелёным, с подсказкой «падеж; значение в карте») и считаются в статистике; опция «Склонять ФИО по контексту» на странице восстановления по умолчанию включена.
**Приёмка:** фикстура `deanon-decline.json` (≥ 40 случаев) — 100 %; `deanon.json` (FR-36) проходит без изменений; e2e `restore.spec.js`.
*Примечание (0.3, FR-36а).* В файле DOCX склонение применяется только к тексту документа (`w:t`, `w:delText`); в атрибутах (авторы правок, alt-тексты, поля), связях и метаданных подставляется значение из карты как есть. Склонение работает в координатах исходного текста (`deanonymizeSpans`), поэтому метка, разбитая на раны, и приклеенное окончание заменяются в документе одной правкой.

### 4.10. Прочее

**FR-38.** Все действия, ведущие к потере данных (загрузить оригинал, сбросить правки, удалить сессию), требуют одного подтверждения.

**FR-39.** В рабочем пространстве (раздел «Недавние») отображается журнал последних 20 операций (имя файла, время, число сущностей/замен, сайт) без исходных значений; хранится в `storage.session`.

**FR-40.** Результат генерируется детерминированно: один и тот же документ с одними решениями даёт побайтно одинаковый `.docx` (фиксированные дата ZIP-записей 1980-01-01, порядок частей как в исходнике, уровень сжатия DEFLATE 6).
**Приёмка:** два прогона → одинаковый SHA-256.

### 4.11. Страница настроек и индикация

**FR-42.** Настройки редактируются на отдельной странице `options.html` (`options_ui.open_in_tab: true`), разделы по 3.4a. Popup не содержит полных настроек — только тумблер перехвата, ссылку «Настройки» и быстрые действия (3.2a). Каждое изменение сохраняется немедленно (без кнопки «Сохранить») с визуальным подтверждением; невалидное значение не сохраняется и подсвечивается.
**Приёмка:** e2e `options.spec`: изменение любого поля отражается в `storage.local` ≤ 200 мс и в открытой вкладке сайта без перезагрузки.

**FR-43.** Индикация состояния перехвата: бейдж на иконке действия — `ON` (зелёный) если `interceptEnabled` и текущая вкладка разрешена; пусто — иначе. Обновляется при смене вкладки, навигации и изменении настроек. Тултип иконки: «DOCX Anonymizer — перехват включён на chatgpt.com» / «перехват выключен».
**Приёмка:** переключение вкладок между разрешённым и запрещённым сайтом меняет бейдж ≤ 300 мс; при выключенном тумблере бейджа нет ни на одной вкладке.

### 4.12. Пользовательские категории

**FR-44.** Пользователь создаёт, редактирует, отключает и удаляет собственные категории. Структура `CustomCategory`:

```json
{
  "id": "custom:project",            // генерируется, неизменяем
  "label": { "ru": "Проект", "en": "Project" },
  "placeholderPrefix": { "ru": "ПРОЕКТ", "en": "PROJECT" },
  "color": "#8e44ad",
  "enabled": true,
  "priority": "belowBuiltin",        // "belowBuiltin" | "aboveBuiltin"
  "kind": "dictionary",              // "dictionary" | "labeled" | "pattern"
  "dictionary": { "values": ["Проект Орион", "Орион"], "caseSensitive": false, "wholeWord": true },
  "labeled":    { "labels": { "ru": ["табельный номер"], "en": ["employee id"] }, "shape": "digits", "minLen": 6, "maxLen": 6 },
  "pattern":    { "regex": "ЗК-\\d{4}/\\d{2}", "flags": "u", "validator": "none" },
  "createdAt": "2026-10-02T10:00:00Z"
}
```

Заполняется только блок, соответствующий `kind`. `shape` ∈ {`digits`, `letters`, `alnum`, `any`}; `validator` ∈ {`none`, `luhn`, `mod97`, `inn`, `ogrn`, `snils`} (переиспользование встроенных). Уровни уверенности: `dictionary` → `labeled`-уровень (точное совпадение из словаря); `labeled` → `labeled`; `pattern` → `weak`, с лейблами (необязательное поле `labels`) → `labeled`. Пересечения со встроенными категориями разрешаются по FR-20; `priority: aboveBuiltin` ставит категорию выше всех встроенных на шаге 3.
**Приёмка:** фикстура `custom-categories.json`: три категории каждого типа находят ожидаемое и не находят негативные примеры; категория с `aboveBuiltin` выигрывает у PERSON на пересечении.

**FR-45.** Форма создания категории содержит поле «Проверить на тексте» (textarea ≤ 10 000 символов): совпадения подсвечиваются при вводе с задержкой 300 мс. Для `kind: pattern` регулярное выражение перед сохранением проверяется в отдельном Worker на тексте-образце из 20 000 символов (включая строки вида `aaaa…a!`); если проверка не завершилась за 500 мс — Worker завершается, сохранение блокируется с сообщением «Шаблон слишком медленный, упростите его». Длина шаблона ≤ 500 символов; флаги ограничены `iu`; lookbehind запрещён.
**Приёмка:** шаблон `(a+)+$` отклоняется; `ЗК-\d{4}/\d{2}` принимается.

**FR-46.** Пополнение словаря из превью: действие «Анонимизировать как…» (FR-31) предлагает список категорий, включая пользовательские, и пункт «Новая категория…»; для словарных категорий после замены предлагается «Запомнить “<значение>” в словаре категории» (одно нажатие). Варианты значения (склонения для кириллицы по FR-23) порождаются автоматически при поиске, в словарь пишется только исходное значение.
**Приёмка:** e2e: добавленное из превью значение находится в следующем документе без действий пользователя.

**FR-47.** Пользовательские категории экспортируются и импортируются файлом `*.categories.json` (схема `schemas/custom-categories.schema.json`), по отдельности и вместе со всей конфигурацией (FR-53). При сохранении словарной категории UI показывает одноразовое предупреждение: «Словарь хранится на диске этого компьютера в профиле браузера; не добавляйте в него данные, которые нельзя хранить локально».
**Приёмка:** экспорт → удаление → импорт восстанавливает категории с теми же `id`.

### 4.13. Рабочее пространство

**FR-48.** Рабочее пространство — страница `workspace.html` во вкладке расширения; открывается из popup, командой `chrome.commands` (`Ctrl+Shift+Y`, настраивается в `chrome://extensions/shortcuts`) и повторно активирует уже открытую вкладку, а не создаёт новую. Приём файлов: drag-and-drop на любую область страницы, кнопка «Выбрать файлы» (`multiple`), кнопка «Обработать папку» (`showDirectoryPicker`, рекурсивно, только `.docx`/`.docm`, пропуская подпапку `anonymized/` и временные `~$*`). Сессии документов, открытых в рабочем пространстве, те же, что у перехвата (один offscreen-хост).
**Приёмка:** e2e `workspace.spec`: 5 файлов через drop → очередь из 5; папка с 3 `.docx` + 2 `.pdf` + вложенной папкой → 4 `.docx` в очереди (включая вложенную), `.pdf` помечены «пропущен».

**FR-49.** Партия: все документы, добавленные одним действием (или вручную объединённые кнопкой «Объединить в партию»), образуют партию с общим маппингом. Нумерация плейсхолдеров сквозная; нормализованное значение, встреченное в любом документе партии, получает один плейсхолдер во всех; KB (FR-22) строится по каждому документу и объединяется. Решение по сущности (включить/выключить/замена) действует на всю партию; исключение отдельного вхождения — только на документ. Статусы файлов: `queued`, `analyzing`, `review`, `applied`, `saved`, `error`, `skipped`.
**Приёмка:** фикстура из договора и приложения: «Иванов П.С.» → `[ФИО_1]` в обоих; выключение INN в одном → выключено в обоих; `_batch.mapping.json` содержит `documents[]` из двух записей.

**FR-50.** Сохранение результатов:
- одиночный файл — `showSaveFilePicker` с предложенным именем `<name><outputSuffix>.docx`; при недоступности API или отказе разрешения — `<a download>`;
- партия из папки — запись в `<папка>/anonymized/<name>.docx` через `FileSystemDirectoryHandle` (запрос разрешения `readwrite` один раз на папку), плюс `_batch.mapping.json` и `_batch.report.html`; существующие файлы перезаписываются только после подтверждения со списком;
- партия без папки — по выбору `batchOutput`: ZIP (`anonymized.zip`, содержимое как в папке) или файлы по одному.
Исходные файлы никогда не изменяются и не удаляются.
**Приёмка:** e2e с временной папкой (Playwright предоставляет директорию через `page.evaluate` + mock `showDirectoryPicker` на `FileSystemDirectoryHandle` из OPFS): в `anonymized/` появляются ожидаемые файлы; исходники побайтно не изменились.

**FR-51.** Повторное применение маппинга: действие «Применить маппинг…» принимает `*.mapping.json` (FR-28); его `entries` загружаются как KB-сущности уровня `kb` с фиксированными плейсхолдерами и `variants`; новые сущности нумеруются после максимального номера в маппинге по категории. Результирующий маппинг содержит объединение (`entries` из загруженного + новые, поле `inheritedFrom` с sha256 исходного маппинга).
**Приёмка:** договор → маппинг; допсоглашение с теми же сторонами + маппинг → те же плейсхолдеры, новое лицо получает следующий номер.

**FR-52.** Профили настроек: именованные наборы полей `categories`, `mode`, `language`, `placeholderLanguage`, `keepMetadata`, `stripEmbedded`, `govEntities`, `dictNames` (версия 0.2), `nerThreshold`. Встроенные: **«Для LLM»** (`llm`: все категории по умолчанию, `placeholder`, ОПФ сохраняются, `govEntities: true`, CONTRACT/AMOUNT выкл.) и **«Для внешней передачи»** (`external`: все 21 категория вкл., `mask` для числовых идентификаторов и `placeholder` для остальных, `govEntities: false`, `stripEmbedded: true`). Пользователь создаёт свои на основе существующего. Активный профиль выбирается в рабочем пространстве, панели и настройках; перехват использует `activeProfile`.
**Приёмка:** переключение профиля в рабочем пространстве до анализа меняет набор категорий; в середине проверки — предлагает «Переанализировать с новым профилем?».

**FR-53.** Отчёт по обработке: `*.report.html` (самодостаточный, без внешних ресурсов): имя файла(ов), дата, профиль, таблица «категория → число сущностей → число замен», список предупреждений, список отключённых пользователем сущностей (категория и плейсхолдер — **без исходных значений**), версия расширения и sha256 исходного и результирующего файлов. Кнопка «Печать». Экспорт/импорт всей конфигурации (`settings` + `customCategories` + `profiles` + `exclusions`) — файл `docx-anonymizer.config.json`.
**Приёмка:** отчёт открывается в браузере офлайн; поиск gold-значений фикстуры в отчёте даёт 0.

### 4.14. PDF с текстовым слоем (версия 0.3, `docs/concept-0.3.md`)

**FR-53.** PDF перехватывается так же, как DOCX (FR-01–FR-06), если `pdfMode` не `off`. Результат — **текст с плейсхолдерами**, а не PDF: `имя.anon.md` (Markdown, по умолчанию) или `имя.anon.txt` (`pdfMode: text`), MIME `text/markdown` / `text/plain`, UTF-8 без BOM. Подставить «[ФИО_1]» во вшитые подмножества шрифтов PDF нельзя, а редактура потоков содержимого хрупка. Панель показывает заметку «Текст PDF уйдёт в чат как .md», «Скачать результат» отдаёт тот же файл.
**FR-54.** Извлечение: pdf.js (Apache 2.0) из пакета расширения (`vendor/pdfjs/`, legacy-сборка, CMaps и стандартные шрифты рядом), во вложенном воркере воркера ядра, без сети (NFR-01). Разметка (`core/pdf/layout.js`): строки по базовой линии, пробелы по зазорам, две колонки — слева направо, абзацы по шагу строк, отступу и заполнению строки, переносы «слово-»/строчная (дефис в «Санкт-Петербург», почте и коротких частях «пр-т» остаётся), заголовки по кеглю (≥ 1.5× — `#`, ≥ 1.2× или жирный короткий абзац — `##`), маркированные списки (`- `), таблицы по выравниванию колонок (`| … |`), колонтитулы (повтор в верхних/нижних 8 % страницы на ≥ 3 или ≥ 50 % страниц, мелкий одиночный крайний текст) и номера страниц удаляются, граница страниц — `---`.
**FR-55.** Модель: блоки → `DocModel` с `kind: 'text'` (`core/text/model.js fromText`), поэтому детекторы, словари, NER, база знаний сторон (таблицы — `doc.tables`), исключения, маппинг и восстановление (FR-36/37) работают без изменений; колонтитулы — потоки в отдельных частях (сущности в них находятся и попадают в карту, в результат текст колонтитулов не идёт).
**FR-56.** Отказы (§3.5): `PDF_NO_TEXT` (на всех страницах < 20 букв), `PDF_ENCRYPTED`, `PDF_EMPTY`, `PDF_INVALID` (`.pdf` без сигнатуры `%PDF-` в первых 1024 байтах или повреждён), `TOO_LARGE` (размер — `maxFileSizeMB`; > 1000 страниц — `details.pages`). Часть страниц без текста — предупреждение `PDF_PAGES_NO_TEXT {details: {pages}}`. Оригинал при отказе уходит только после явного «Загрузить как есть».
**Приёмка:** К1–К9, К11–К13, К17 из `docs/concept-0.3.md`: `tests/unit/pdf/*`, `tests/unit/{text-model,apply-text}.spec.js`, `tests/integration/pdf-{fixtures,pipeline}.spec.js`, e2e `pdf.spec.js`, `nfr.spec.js`.

## 5. Архитектура

### 5.1. Компоненты

```
┌──────────────────────────────┐    port "docx"     ┌──────────────────────┐
│ content script (страница)    │◄──────────────────►│ background (SW)      │
│ - перехват input/drop/paste  │  chunked base64    │ - роутер сообщений   │
│ - панель (Shadow DOM, ui/)   │                    │ - lifecycle offscreen│
└──────────────────────────────┘                    │ - storage.session    │
┌──────────────────────────────┐    port "docx"     │   (индекс сессий)    │
│ workspace / options / popup  │◄──────────────────►│                      │
│ - файл, превью, восстановить │                    └──────────┬───────────┘
└──────────────────────────────┘                               │ runtime.sendMessage
                                                               ▼  (target: "offscreen")
                                                    ┌──────────────────────┐
                                                    │ offscreen document   │
                                                    │ - Web Worker: core/  │
                                                    │   (JSZip, парсер,    │
                                                    │    детекторы, NER на │
                                                    │    ONNX Runtime Web) │
                                                    │ - сессии документов  │
                                                    └──────────────────────┘
```

| Компонент | Обязанности | Чего не делает |
|---|---|---|
| `content/` | Перехват событий, панель, передача файла, подстановка результата, скачивание через `<a download>` | Не разбирает документ, не хранит сущности дольше жизни панели |
| `background.js` | Маршрутизация портов ↔ offscreen, создание/закрытие offscreen, индекс сессий, миграция настроек при `onInstalled` | Не выполняет ядро |
| `offscreen/` | Хост ядра: загрузка WASM/модели, Web Worker с ядром, память сессий, прогресс | Не имеет UI |
| `core/` | Чистые функции: `parseDocx`, `buildStreams`, `detect`, `resolveOverlaps`, `applyDecisions`, `buildMapping`, `deanonymize`, `categories`, `validators`, `settings` | Не зависит от `chrome.*` (тестируется в Node) |
| `ui/` | Компоненты превью, таблицы, панели; используются content, workspace и options | Не содержит логики поиска |
| `popup/` | Компактное меню: открыть рабочее пространство, тумблер перехвата, недавние, «Восстановить» | Не обрабатывает файлы |
| `workspace/` | Страница рабочего пространства: очередь, партии, папки (File System Access API), превью (`ui/`), сохранение, отчёт | Не выполняет ядро — клиент протокола 5.4 |
| `options/` | Страница настроек: перехват, категории (встроенные и свои), профили, исключения, экспорт/импорт | — |

Единое ядро закрывает дефект 2: один путь обработки для рабочего пространства и перехвата — ядро исполняется только в offscreen, workspace, popup и content — тонкие клиенты одного протокола.

### 5.2. Решения

**Хост обработки.** Варианты: (а) service worker с `importScripts` + keep-alive (прототип); (б) offscreen-документ с Web Worker; (в) обработка в content script. Выбран **(б)**: offscreen живёт пока его не закроет background (нет 30-секундного лимита SW), поддерживает WASM и Workers (нужно для ONNX Runtime), CSP страницы на него не действует, модель загружается один раз на сессию. (а) не подходит из-за выгрузки SW и отсутствия Workers; (в) — из-за блокировки UI страницы и загрузки модели ≥ 50 МБ в каждую вкладку.

**Жизненный цикл offscreen.** Создаётся background'ом по первому запросу (`reasons: ["WORKERS"]`, `justification` описана), закрывается через 10 мин без активных сессий-запросов (сессии документов при этом сериализуются в `storage.session` только как решения — исходные данные теряются, FR-29; UI предупреждает «Сессия завершена, загрузите файл заново»). Пока открыт порт от content/workspace/popup, background считается активным (сообщения по порту продлевают SW); heartbeat не нужен.

**Передача бинарных данных.** Варианты: (а) base64 одной строкой; (б) base64 чанками по порту; (в) `URL.createObjectURL` — не работает между origin'ами. Выбран **(б)**: `FileReader.readAsDataURL` (нативное base64, без посимвольной конкатенации — дефект 7), чанки по 4 МиБ (лимит сообщения 64 МиБ), сборка в offscreen через `Uint8Array` фиксированного размера; результат возвращается так же. Между background и offscreen данные передаются теми же чанками (JSON-сериализация `runtime.sendMessage`).

**CSP.** `manifest.content_security_policy.extension_pages = "default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'"`. `connect-src 'self'` блокирует любые сетевые запросы из страниц расширения на уровне платформы (NFR-01). Стили панели — строка внутри JS content script (без `web_accessible_resources`, дефект 10). `web_accessible_resources` — пусто.

**NLP.** Варианты: (а) `Babelscape/wikineural-multilingual-ner` (mBERT, 9 языков включая RU и EN, ≈ 180 МБ int8); (б) пара компактных моделей: RU — fine-tune `cointegrated/rubert-tiny2` для NER (≈ 12–30 МБ int8), EN — distil/bert-base-NER (≈ 65–110 МБ int8); (в) GLiNER multi (≈ 350 МБ int8, zero-shot). Выбор делается на этапе 0 (spike) по метрикам раздела 8 на dev-корпусе при ограничении суммарного размера моделей **≤ 200 МБ** и времени анализа 300-страничного документа ≤ 60 с (NFR-05). Предпочтение по умолчанию — **(а)** как одна модель на оба языка с задокументированной поддержкой русского; **(б)** — если (а) не укладывается в NFR-05 на эталонной машине. (в) отвергается по размеру. Модель и токенизатор лежат в пакете расширения (`models/`), загружаются через `chrome.runtime.getURL` (это не сетевой запрос); бэкенд ONNX Runtime Web — WASM с SIMD, одна нить (SharedArrayBuffer недоступен без cross-origin isolation). Вход NER — параграфы, окна по 256 токенов с перекрытием 32; выход — спаны PER/ORG/LOC с вероятностью; порог `nerThreshold`. Интерфейс `core/ner/NerProvider` с реализацией `OnnxNerProvider` и `NullNerProvider` (для тестов и `nerEnabled=false`).

> **Отклонение (версия 0.2, WP8).** Модель **не входит** в пакет расширения и не лежит в `models/`: репозиторий публичный, весов модели в git нет. ## 6. Алгоритм работы с DOCX

### 6.1. Разбор

1. Проверка сигнатуры: `50 4B 03 04` → ZIP; `D0 CF 11 E0` → `ENCRYPTED`; иначе `NOT_DOCX`.
2. JSZip загружает контейнер; обязательна часть `word/document.xml`, иначе `NOT_DOCX`. Части из FR-10 читаются как строки UTF-8 (`TextDecoder`), остальные остаются бинарными и копируются без изменений.
3. **Токенизация XML.** Варианты: (а) регулярки по строке (прототип); (б) `DOMParser`/`XMLSerializer` в offscreen; (в) собственный линейный токенизатор тегов с байтовыми смещениями. Выбран **(в)**: (а) ломается на вложенных `<w:p>` и не знает о границах элементов (дефект 4); (б) при ре-сериализации меняет объявления namespace, самозакрывающиеся теги и XML-декларацию, что Word терпит не всегда, и удваивает память на 50-МБ частях. Токенизатор проходит строку один раз, выдаёт события `open/close/selfclose/text` с именем, атрибутами (сырой строкой) и смещениями `[start,end)`; стек элементов отслеживает контекст (`w:p` → `w:r` → `w:t`). Все остальное содержимое остаётся нетронутыми байтами.
4. **Модель.** На каждый `<w:p>` (с учётом вложенности — свой параграф для каждого `w:p` на стеке) строятся потоки `live`, `deleted`, `field`. Внутри параграфа текстовые элементы попадают в поток по типу: `w:t` → live, `w:delText` → deleted, `w:instrText`/`w:delInstrText` → field. Элементы `w:r` внутри `w:hyperlink`, `w:sdtContent`, `w:smartTag`, `w:fldSimple`, `w:ins`, `w:del`, `w:moveTo` принадлежат ближайшему `w:p`.

### 6.2. virtualText и charMap

Для каждого потока:
- текст `<w:t>` XML-unescape'ится (5 стандартных сущностей + числовые `&#…;`); charMap хранит соответствие индекса virtualText → (ран, индекс в unescaped-тексте рана); для записи обратно хранится исходный escaped-диапазон;
- `<w:tab/>` → `\t`; `<w:br/>`, `<w:cr/>` → `\n`; `<w:sym/>` → `￼`; `<w:noBreakHyphen/>` → `‑`; `<w:softHyphen/>` → **пропускается** (не добавляет символ, но charMap помечает позицию, чтобы при замене диапазон, пересекающий мягкий перенос, удалил элемент); `<w:ptab/>` → `\t`; `<w:footnoteReference/>`, `<w:commentReference/>`, `<w:drawing>`, `<w:pict>` → `￼`;
- `xml:space="preserve"` не влияет на построение: пробелы берутся как есть;
- `￼` и `\n` являются границами для всех детекторов (сущность не может их содержать), `\t` — допустимый разделитель внутри ADDRESS и PHONE.

**Приёмка (NFR-independent):** фикстура `virtualtext.json` с 30 параграфами (табы, переносы, soft hyphen внутри ИНН «7736­050003» → находится как ИНН; `&amp;` внутри названия компании; `<w:t>` разбитый на 5 ранов посимвольно).

### 6.3. Замена

Вход: список правок `{part, stream, start, end, newText}` в координатах virtualText. Алгоритм:
1. Правки сортируются по убыванию `start` внутри части (справа налево), пересечения исключены этапом FR-20.
2. Для правки находятся затронутые раны `r_first..r_last` через charMap. В `r_first` текст = `prefix + escape(newText)`, где `prefix` — unescaped-текст рана до `start`; в `r_last` текст = `suffix`; промежуточные раны получают пустой `<w:t/>` (ран и `<w:rPr>` сохраняются — форматирование не теряется). Если `r_first == r_last` — `prefix + escape(newText) + suffix`.
3. Если новый текст рана начинается/заканчивается пробелом или пуст — у `<w:t>` выставляется `xml:space="preserve"` (добавляется, если отсутствовало).
4. Спецэлементы внутри диапазона (`w:tab`, `w:softHyphen`, `w:br`) удаляются; элементы вне диапазона не трогаются.
5. Правки применяются к строке части как замены байтовых диапазонов справа налево — смещения левее не сдвигаются.
6. Атрибутные правки (`w:author`, `descr`, `Target`) — отдельный список замен значений атрибутов с экранированием кавычек.
7. Части, в которых правок не было, в ZIP копируются как исходные байты (без перекодирования), включая `word/media`.

**Валидность.** Результат обязан: открываться в Word 2016+ и LibreOffice 7+ без диалога восстановления; проходить `xmllint --noout` на всех изменённых частях; содержать те же части, что исходник (минус удалённые по FR-12/FR-15), с теми же `[Content_Types].xml`-записями.
**Приёмка:** набор «файл → файл» (раздел 9.2).

### 6.4. Производительность разбора

Токенизатор — однопроходный, без создания объектов на каждый символ; строки частей держатся один раз; charMap — типизированные массивы (`Uint32Array` для индексов ранов и смещений). Оценка памяти: ≤ 12 × размер XML-части.

## 8. Качество распознавания

### 8.1. Корпус

| Поднабор | Состав | Количество | Разметка |
|---|---|---|---|
| `synth-ru` | договоры поставки, оказания услуг, аренды, NDA, трудовые, займа; сгенерированы из 12 шаблонов генератором `tools/gen-corpus` с подстановкой синтетических сущностей (валидные контрольные суммы, случайные ФИО из словарей, адреса из генератора) | 40 | автоматическая (генератор знает, что подставил) + ручная проверка 10 |
| `synth-en` | service agreement, NDA, SPA, employment, loan — 8 шаблонов | 25 | автоматическая |
| `synth-mixed` | двуязычные (две колонки / последовательные блоки) | 10 | автоматическая |
| `hard` | ручные документы с рецензированием, текстовыми полями, колонтитулами, сносками, комментариями, таблицами реквизитов, разбитыми на раны словами, soft hyphen, полями | 15 | ручная (инструмент — вкладка «Текст» рабочего пространства в режиме «Разметка», экспорт `*.gold.json`) |
| `real-private` | реальные договоры заказчика; хранятся **только локально**, не в репозитории, путь задаётся переменной `CORPUS_PRIVATE_DIR` | ≥ 10 | ручная |

Формат разметки: `{"document": "<name>", "entities": [{"category","value","occurrences":[{"part","pid","stream","start","end"}]}]}` в координатах virtualText (стабильны при изменении XML-токенизатора только если не меняется 6.2; версия формата фиксируется).

### 8.2. Метрики

Для каждой категории: precision, recall, F1 на уровне вхождений (совпадение категории и точных границ; для PERSON/COMPANY/ADDRESS допускается нестрогое совпадение границ — IoU ≥ 0.8). Дополнительно: «утечка» — число вхождений любой включённой категории с gold-разметкой, оставшихся в результирующем документе (проверяется поиском gold-значений в virtualText результата, а не по спанам).

### 8.3. Целевые пороги (корпус без `real-private`; на `real-private` — отчёт без порога)

| Категория | Recall | Precision |
|---|---|---|
| INN, OGRN, SNILS, ACCOUNT, CARD, PASSPORT, IBAN (включённые) | **1.00** (нулевая терпимость; любая утечка валидного или помеченного лейблом значения = провал CI) | ≥ 0.98 |
| KPP, BIK, SWIFT, SSN, TAXID, EMAIL, PHONE, URL | ≥ 0.98 | ≥ 0.97 |
| PERSON | ≥ 0.95 | ≥ 0.90 |
| COMPANY | ≥ 0.93 | ≥ 0.90 |
| ADDRESS | ≥ 0.85 | ≥ 0.85 |
| BIRTHDATE | ≥ 0.95 | ≥ 0.95 |
| CONTRACT, AMOUNT (выкл. по умолчанию) | ≥ 0.80 | ≥ 0.80 |

Нулевая терпимость формально: `leak(INN ∪ OGRN ∪ SNILS ∪ ACCOUNT ∪ CARD ∪ PASSPORT ∪ IBAN) == 0` на всех документах корпуса при настройках по умолчанию.

### 8.4. Процесс

`npm run eval` считает метрики, пишет `eval/report.md` с таблицей и списком ошибок (FP/FN с контекстом ±40 символов, только для синтетических поднаборов). Отчёт сравнивается с `eval/baseline.json`; падение recall любой категории > 0.01 — провал CI.

Для каждого документа `fixtures/docs/*.docx` с ожидаемым `*.expected.json` (сущности) и `*.expected.docx` (результат при решениях по умолчанию):
1. анализ → сравнение сущностей;
2. применение → распаковка результата → для каждой изменённой части `xmllint --noout` (через `child_process`, Docker-образ CI содержит libxml2) и сравнение с ожидаемым по нормализованному XML;

**Сборщик.** Варианты: (а) без сборщика (ESM напрямую, `importScripts` в воркере); (б) esbuild; (в) Vite + CRXJS. Выбран **(б) esbuild**: нужен бандлинг ESM-ядра в один файл для Web Worker и content script (content script не поддерживает ESM-импорты), подключение `jszip` и `onnxruntime-web` из `node_modules`; esbuild делает это одним скриптом за < 1 с без плагинной экосистемы (в) и без ограничений (а). Точки входа: `background`, `content`, `offscreen`, `worker`, `workspace`, `options`, `popup`. Sourcemaps — только в dev-сборке.

**Зависимости без сети при сборке.** `package-lock.json` фиксирует версии и integrity; `npm ci` выполняется один раз при настройке окружения; `npm run build` не обращается к сети (esbuild читает `node_modules`). WASM-файлы ORT копируются из `node_modules/onnxruntime-web/dist/` в `vendor/`. Модели: `tools/fetch-models.sh` скачивает выбранные файлы один раз, проверяет sha256 из `models/index.json`; в CI модели берутся из git LFS. Запрещён `importScripts`/`<script src>` с внешних URL (линт-правило).

**Отклонение (версия 0.2, WP8).** Модели в git и в архиве расширения нет (ни LFS, ни `models/index.json`). Пакет модели собирает `npm run pack:model -- --id=<id>` из `models-src/<id>/` (детерминированный zip в `release/`, sha256 печатается и вносится в `src/core/ner/known-packs.js` для пометки «проверен»), публикуется в GitHub Releases отдельно от расширения. Worker offscreen-документа собирается отдельным вызовом esbuild как ES-модуль (`format: 'esm'`; `onnxruntime-web/wasm` находит wasm через `import.meta.url`) и создаётся как `new Worker('worker.js', {type: 'module'})`; остальные бандлы — IIFE. В `dist/vendor/` копируются только `ort-wasm-simd-threaded.wasm` (13,6 МБ) и лицензия ORT — JS-glue встроен в `worker.js`.

**Отклонения версии 0.2.0 от структуры выше.** Фактическая раскладка — `docs/contracts.md` §0 «Карта кода»: тесты в `tests/{unit,integration,e2e,fixtures}`, скрипты в `scripts/*.mjs`, обучение модели — `tools/ner-train/` (Python, uv), исходники пакета модели — `models-src/<id>/` (вне git). Нет `workspace/`, `models/`, `docs/ner-spike.md`, `bench/`, `fixtures/perf/`; `vendor/` появляется только в `dist/`. Используется `fflate`, а не JSZip; ESLint 10 без `eslint-plugin-security` и без правила о кириллице. Архив релиза — `release/docx-anonymizer-<версия>.zip` (`npm run pack`); версия манифеста в репозитории совпадает с `package.json` (тест). CI — `.github/workflows/ci.yml` (lint, тесты, сборка, архив, e2e), без LFS и без сборки по тегу.

**Версия 0.3 (WP10-C): два архива.** `npm run pack` собирает лёгкий `release/docx-anonymizer-<версия>.zip` (без `models/`, побайтно как раньше) и,
если есть пакет модели (`--model=<zip>` или единственный `release/docx-anonymizer-ner-*.zip` от `npm run pack:model`), полный
`release/docx-anonymizer-<версия>-full.zip`: `node scripts/build.mjs --with-model=<zip>` кладёт zip пакета в `models/` как есть и пишет `models/index.json`;
пакет не из `KNOWN_PACKS` — сборка падает («не в KNOWN_PACKS»). Каждый архив собирается в свою временную стадию (define `__BUNDLED_MODEL__` запечён в бандлы),
оба воспроизводимы; запись `models/*.zip` в архиве — без сжатия (`level: 0`). Модели по-прежнему нет в git и в CI: там собирается только лёгкий архив.
Порядок релиза: `npm run pack:model` → sha256 в `src/core/ner/known-packs.js` → `npm run pack` → в Releases три файла (лёгкий, полный, пакет модели).

**Линтер:** ESLint 9 (flat config) + `eslint-plugin-security` + кастомные правила: запрет литералов с кириллицей вне `_locales` и фикстур; запрет `console.log` с переменными, кроме белого списка; запрет `fetch`/`XMLHttpRequest`/`WebSocket` вне `tools/`.

**Упаковка и релиз:** `npm run package` → `dist/docx-anonymizer-<version>.zip` с `manifest.json` в корне, без sourcemaps, тестов и `tools/`; `version` берётся из `package.json` и дублируется в манифест при сборке. Релиз = git-тег `v<version>` + архив и его sha256 в GitHub Releases (workflow собирает архив из тега, чтобы любой мог сверить сборку с исходниками). Структура соответствует требованиям Web Store на случай будущей публикации.

## 13. Допущения

Зафиксированы по ответам заказчика и выбранным вариантам по умолчанию:

1. **Браузеры:** Chrome и Edge (Chromium) ≥ 120; Firefox/Safari — вне рамок.
2. **Деанонимизация:** текст ответа (FR-36) и, с 0.3, файл от ИИ — `.docx`/`.docm`/`.md`/`.txt` (FR-36а); `.xlsx`/`.pptx` и PDF от сервиса не восстанавливаются.
3. **Форматы:** только `.docx`/`.docm`; расширяемость через `DocumentAdapter`.
4. **NLP обязателен в v1:** ONNX Runtime Web (WASM) в offscreen-документе; выбор модели — spike этапа 0 с ограничениями 5.2; модель бандлится в пакет; сеть не используется.
5. **Открытый проект на общественных началах:** публичный репозиторий с лицензией MIT, релизы — `.zip` в разделе Releases, установка вручную по README; никакого сервера, телеметрии, общей конфигурации и шифрования; требования Web Store соблюдаются как гигиена, публикация — по желанию позже.
5a. **Автоперехват выключен по умолчанию**; при включении — allowlist из 5 LLM-сайтов. Основной путь — рабочее пространство (С1); ответственность за решение об анонимизации — на пользователе, инструмент не делает ничего без явного действия.
5b. **Пользовательские категории** трёх типов хранятся в `storage.local` без шифрования, ограничены 100 категориями и 5 000 значений в словаре суммарно.
5c. **Партия** = файлы, добавленные одним действием; результаты папки пишутся в подпапку `anonymized/`, исходники не изменяются.
6. **Обязательные сайты:** ChatGPT, Claude.ai, Gemini, DeepSeek, Perplexity — проверяются вручную перед релизом (`e2e:sites`), автоматическая CI-проверка — только тестовая страница.
7. **Новые категории:** PASSPORT, SNILS, BIRTHDATE, CARD добавлены к 17 из прототипа (всего 21).
8. Паспортные данные входят в список нулевой терпимости (8.3).
9. Интерфейс по умолчанию следует языку браузера; плейсхолдеры — языку документа.
10. Лимит размера файла 50 МБ по умолчанию, до 100 МБ в настройках.
11. Текст `mask` — `X` для всех буквенно-цифровых символов; `delete` — `[удалено]`/`[redacted]`.
12. ОПФ и кавычки компании сохраняются вне плейсхолдера.
13. Эталонная машина для NFR: 4 ядра ≥ 3 ГГц, 16 ГБ RAM.
14. Реальные договоры для оценки хранятся вне репозитория.
