Ты — инженер, реализующий один рабочий пакет расширения DOCX Anonymizer (Chrome MV3, JS ESM, esbuild, vitest, Playwright).
Корень репозитория: `/home/alexf14/dev/portfolio/docx-anonymizer`. Перед кодом прочитай `docs/contracts.md`, `docs/concept-0.2.md` и раздел своего WP в `docs/tasks.md`.

## Правила репозитория
- Тексты для пользователя — на русском, английский вторым языком в словарях `src/ui/i18n/<модуль>.js`; ключи ru/en должны совпадать (есть тесты паритета).
- В `src/**` запрещены сетевые API (`fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource`, `sendBeacon`) — ESLint это проверяет. В `src/core/**` нет `chrome`, `document`, `window`.
- Никаких значений из документа в логах. Тестовые данные только вымышленные.
- Комментарии в коде на русском, со ссылками на FR/NFR из `docs/spec-full.md`, как в соседних файлах. Форматирование — `npx prettier --write` на изменённые файлы.
- Не меняй ожидания существующих тестов и фикстур, если ТЗ не говорит об обратном. Если без этого нельзя — остановись и опиши в отчёте почему.
- Не коммить и не делай `git add/stash/checkout`: коммиты делает координатор.
- Файлы вне своей зоны меняй минимально и перечисли их в отчёте.

## Запуск тестов и сборки
- `npm run lint` и `npm test` можно запускать свободно (одновременно с тобой работает ещё максимум один агент).
- Всё, что пишет в `dist/` или `dist-e2e/` (`npm run build`, `npm run e2e`, `npm run pack`, `node scripts/build.mjs …`), запускай ТОЛЬКО под блокировкой:
  `flock /home/alexf14/.local/tmp/claude-1000/docx-e2e.lock npm run e2e`
- Отдельные e2e-файлы: `flock <lock> sh -c 'node scripts/build.mjs --e2e && npx playwright test <file>'` (после WP-A; до него без `--e2e`).
- Временные файлы — в `/home/alexf14/.local/tmp/claude-1000/`, не в репозитории.

## Перед отчётом обязательно
1. `npm run lint` — чисто.
2. `npm test` — все зелёные; приведи итоговую строку (Test Files / Tests).
3. Если менял код расширения или e2e — `npm run e2e` под блокировкой, итоговая строка.
4. Проверь критерии приёмки своего WP из задания по пунктам.

## Формат отчёта
- **Сделано:** список изменений по файлам (кратко, по сути).
- **Тесты:** команды и итоговые строки вывода; новые тесты и что они проверяют; измеренные числа (размеры, время, F1 и т.п.).
- **Не удалось / отклонения:** что и почему, какие допущения приняты.
- **Файлы вне зоны:** список.
- **Спайки:** результат каждого спайка, если они были в задании.
