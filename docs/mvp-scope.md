Полное ТЗ: `docs/spec-full.md` (v1.1). Первая версия реализует **главный сценарий**:

> Человек в окне ChatGPT / Claude / другого LLM-сервиса прикладывает договор `.docx`.
> Расширение перехватывает файл ДО отправки, локально (без единого сетевого запроса) находит
> персональные и коммерческие данные и заменяет их плейсхолдерами (`[ФИО_1]`, `[КОМПАНИЯ_1]`, `[ИНН_1]`).
> В сервис уходит обезличенный `.docx` с сохранённым форматированием. Карта «плейсхолдер → значение»
> остаётся у пользователя; ответ ИИ можно вставить в расширение и получить текст с реальными значениями.

## Входит
1. **Перехват на сайте (С2):** выбор файла в `input[type=file]`, drag&drop, вставка из буфера; в т.ч. `multiple`. Панель в Shadow DOM: «найдено N сущностей», превью, снятие галочек с отдельных сущностей, кнопки «Анонимизировать / Отправить оригинал / Отмена». Перехват включается пользователем (в popup / настройках), по умолчанию — выключен на всех, кроме списка известных LLM-сайтов? — следовать ТЗ (FR-07, FR-34, FR-42, FR-43).
2. **Ядро DOCX:** разбор `document.xml`, колонтитулы, сноски, комментарии и прочие части по ТЗ §4.2; virtualText/charMap (§6.2); замена через runs с сохранением форматирования (§6.3); метаданные `docProps`; детерминированный ZIP; файл открывается в Word без восстановления.
3. **Детекторы по правилам** (без NER): каталог категорий ТЗ §4.3 — регулярки, метки («ИНН:», «р/с», «в лице»), контрольные суммы (ИНН 10/12, ОГРН/ОГРНИП, БИК, КПП, счёт с БИК), PERSON/COMPANY по меткам и паттернам (ФИО, «ООО «…»», инициалы), ADDRESS по меткам и шаблонам; разрешение пересечений §4.4; база знаний сторон §4.5 (морфология падежей, транслитерация) — в объёме, достаточном для договоров.
4. **Замена и маппинг:** режимы плейсхолдер / маска / удаление (§4.6); одно значение → один плейсхолдер по всему документу (и по файлам одной отправки); экспорт маппинга.
5. **Обратная замена (С3):** вставить ответ ИИ → текст с реальными значениями (§4.9).
6. **Настройки:** включение перехвата и список сайтов, категории вкл/выкл, режим замены, язык RU/EN, исключения (§4.8, §4.11 — базово); свои категории — словарь и regex с защитой от катастрофического бэктрекинга (§4.12, базово).
7. **Popup:** тумблер перехвата, недавние сессии, «Восстановить»/обратная замена.

## Не входит (следующие версии)
- NER-модель (ONNX) — §5.2 NLP, этап 4 плана; архитектура оставляет интерфейс `NerProvider` с реализацией-заглушкой.
- Рабочее пространство с партиями и папками (С1, §4.13, этап 5a).
- Корпус и метрики качества §8 (кроме синтетических фикстур для тестов).
- Проверка на реальных сайтах — вручную владельцем.

## Технологии (по ТЗ §10)
Chrome MV3, ES-модули, esbuild, JSZip (или fflate), offscreen document + Web Worker для ядра, Vitest (Node 20) для `core/`, Playwright (Chromium `--load-extension`) для e2e на локальной тестовой странице. Никаких сетевых запросов из расширения (CSP `connect-src 'self'`).
